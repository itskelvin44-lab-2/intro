Anyone signed in can browse, save, request a viewing, list a property and chat once a request is accepted. There is one account type, no separate landlord and tenant roles. Each person's preferences (target rent, ideal bedrooms, preferred areas, wanted amenities) produce a 0 to 100 match score that ranks the feed. Rent is in whole Kenyan shillings per month. Live app: finder.house-app.workers.dev

System architecture

The front end is three static files. The public key ships in the browser, so anyone can send any request the API allows. That is why every rule lives in the database, not in the page.

Solid arrows: the browser calls Supabase with the public key and the user's session. Dashed: live updates pushed back.

Request a viewing, then chat

The core flow. Both people can chat only after the owner accepts, and the accept step is a single all-or-nothing transaction.

Publishing a listing

  1. Photos are resized in the browser (longest side 1600 px, JPEG).
  2. Each photo uploads to the listing-photos bucket under your own folder.
  3. One call to create_listing validates everything and inserts every row atomically.
  4. If any step fails, the browser deletes the files it uploaded.

Status rules

Only active listings show to other people and accept new requests. A listing can be deleted from any state.

Data model

15 tables. Lookups (neighborhoods, amenities) are readable by signed-in users and never writable from the browser.

Match score

Each listing is scored 0 to 100 against the viewer's stored preferences: how close the rent is to the target, how close the bedrooms are to the ideal, whether the area is preferred, and how many wanted amenities it has. Only the preferences a person actually set count, and owners see no score on their own listings.

Security and privacy

  • Row-level security is on for all 15 tables. Anonymous visitors can run no function and read no table.
  • Listings, requests, conversations, saves and views change only through the 12 server functions, which check who is asking.
  • Direct writes are limited to your own profile (some columns), your own preferences and chat messages.
  • Storage: uploads and deletes only inside your own folder, JPEG only, 5 MB for listing photos and 1 MB for avatars.
  • Chat messages are rate limited and capped at 2000 characters.
  • Server functions run with a fixed search path so they cannot be hijacked.
Open app
Stack: HTML, CSS and plain JavaScript; Supabase (Postgres, Auth, Storage, Realtime); Cloudflare hosting. Times are stored in UTC and availability follows the Nairobi date. New towns are added by adding neighborhood data, not by changing code.
